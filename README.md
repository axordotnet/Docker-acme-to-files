# Docker-acme-to-files

[![Test and publish](https://github.com/axordotnet/Docker-acme-to-files/actions/workflows/ci.yml/badge.svg)](https://github.com/axordotnet/Docker-acme-to-files/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)

**One Traefik `acme.json` → one destination directory, ready for other applications.**

[Documentation française](docs/README.fr.md) · [Security](SECURITY.md) · [Contributing](CONTRIBUTING.md)

Exports certificates issued by Let's Encrypt or another ACME CA from **Traefik v2/v3 storage**.
`acme.json` is a Traefik storage format, not a universal Let's Encrypt format. Certbot and
acme.sh directories and Traefik v1 storage are not supported.
This tool does not request or renew certificates: Traefik remains responsible for issuance.

## Features

- PEM certificate, unencrypted PKCS#8 private key, full chain and encrypted PKCS#12/PFX.
- RSA and ECDSA; multiple resolvers, domains, SANs and wildcard certificates.
- Offline polling, including source files replaced by rename; one-shot mode available.
- Validation before publication: key match, validity dates, SAN metadata, supplied chain signatures.
- Complete generation published by atomic `current` symlink replacement; last valid output retained on error.
- Non-root image, restrictive permissions, Docker health check, no Docker socket or network needed.
- Linux AMD64 and ARM64 builds, SBOM and provenance generated by GitHub Actions.

## Quick start (Linux Docker Compose)

```sh
git clone https://github.com/axordotnet/Docker-acme-to-files.git
cd Docker-acme-to-files
install -d -m 700 input output secrets
umask 077
openssl rand -base64 32 > secrets/pfx_password.txt
```

Use your existing ACME directory as `ACME_SOURCE_DIR` (it must contain `acme.json`).
Select a numeric UID/GID that can read the source and password and write the output.
The default is `10001:10001`. For example, for a newly prepared output/secret directory:

```sh
sudo chown 10001:10001 output secrets secrets/pfx_password.txt
printf 'ACME_SOURCE_DIR=/srv/traefik/acme\nCERT_OUTPUT_DIR=./output\nEXPORT_UID=10001\nEXPORT_GID=10001\n' > .env
docker compose up -d
docker compose logs -f acme-to-files
```

**Do not make `acme.json` world-readable or change its owner blindly.** Traefik normally
uses mode `0600`. Match its owner UID when appropriate or arrange a protected readable
copy in a dedicated directory. All parent directories must allow traversal by that UID.
On Synology, check ACLs as well as Unix modes. Compose file-backed secrets also need readable
host permissions; `uid`/`gid` declarations do not reliably change bind-mounted secret ownership.

Mount the **source directory**, not just `acme.json`, so replacements are visible.
Only `acme.json` is read. Prefer a dedicated source directory rather than exposing unrelated secrets.
The container runs offline; image pulls/builds still require network access on the Docker host.

## Output contract

For resolver `letsencrypt` and domain `example.org`, use:
`output/current/letsencrypt/example.org/`.
For `*.example.org`, use `wildcard_example.org`. Resolver/domain names are normalized
to lowercase; collisions are rejected. SANs share their certificate's main-domain folder.

| File | Content | Sensitive |
| --- | --- | --- |
| `certificate.cert` | Leaf X.509 certificate in PEM encoding | No private key |
| `private.key` | Unencrypted PKCS#8 PEM private key | **Yes** |
| `fullchain.pem` | Leaf + supplied intermediate certificates | No private key |
| `chain.pem` | Supplied intermediates only; empty if none | No private key |
| `bundle.pfx` | Key + leaf + supplied chain, password encrypted | **Yes** |
| `combined.pem` | Key + full chain; opt-in `--combined-pem` | **Yes** |

`.cert` is PEM, not binary DER. A `.pem` suffix alone does not specify whether a key is
included. PFX uses modern encryption; old importers requiring legacy RC2/3DES are not supported.
All output files use mode `0600`, generated directories `0700`, owned by the running UID/GID.
Consumers must use that UID or a separately secured copy/distribution mechanism.

Mount the **whole output directory** read-only into consumer containers. Mounting `current`
alone, or individual files, can pin an old generation after renewal. Example paths:
`/certs/current/letsencrypt/example.org/fullchain.pem` and `.../private.key`.

The exporter retains the active and one previous generation. Removed source certificates
disappear from the new active generation; an empty or invalid source preserves the old one.
The output directory is exporter-owned: do not store other data in it. Older generations
are removed after publication. Crash leftovers are cleaned on a later successful publication.

Publication is atomic at the directory pointer, **not across independent consumer opens**.
For strict pair consistency, resolve `current` once and read all files from that resolved
generation; finish before two subsequent publications. Reload the consumer after an export
(or monitor the `current` link). No service restart hooks or Docker socket access are provided.
Use a local Linux filesystem with atomic rename and symlink semantics; NFS/SMB destinations
are not validated. Atomic visibility is not a guarantee against power-loss durability issues.

## Configuration

| CLI option | Environment | Default |
| --- | --- | --- |
| `--source` | `ACME_SOURCE` | `/input/acme.json` |
| `--output` | `OUTPUT_DIR` | `/output` |
| `--password-file` | `PFX_PASSWORD_FILE` | Required for PFX |
| `--interval` | `POLL_INTERVAL` | `30` seconds; range 1–86400 |
| `--once` | — | Export once; exit 0 on success, 1 on export error |
| `--no-pfx` | — | Omit PFX; password file not required |
| `--combined-pem` | — | Include key + chain in one PEM |
| `--healthcheck` | — | Exit 0 if last validation succeeded and is recent |

Password: 12–4096 bytes, no NUL; trailing CR/LF is removed to support secret files.
Use a randomly generated password. Password changes are detected at the next poll.
No plaintext password argument or password environment variable is accepted.
For PEM-only Compose usage, set `command: ["--no-pfx"]` and remove the secret mapping,
`PFX_PASSWORD_FILE`, and top-level `secrets` section.

```sh
docker compose run --rm acme-to-files --once
docker compose run --rm acme-to-files --help
```

One instance maps one file to one output directory. For several sources, create one service
per source with distinct output directories. A filesystem lock prevents concurrent writers
using the same output. Configuration/lock errors exit with code 2. Watch mode retries transient
failures and becomes unhealthy while retaining the last export; Docker does not automatically
restart a container solely because it is unhealthy. Monitor health and certificate expiry.

## Image tags and builds

```sh
docker pull ghcr.io/axordotnet/docker-acme-to-files:latest
docker build --pull -t acme-to-files:local .
```

`latest` follows tested `main`; `sha-<full-commit-sha>` identifies a build; a pushed `vX.Y.Z`
tag publishes `X.Y.Z` and `X.Y`. For production, pin the **image digest** rather than `latest`.
The build uses pinned Python requirements and SHA-pinned Actions; the Python base image
tracks upstream patch updates. Builds are therefore not bit-for-bit reproducible.
Weekly CI rechecks tests/dependencies but does not automatically republish the image.
Rebuild/release after base-image security updates. Dependabot proposes dependency updates.

GHCR packages may initially be private even for a public repository. The final CI job tests
an anonymous pull. If it fails with access denied, the owner must set the package visibility
to **Public** in its package settings, then rerun the failed job. Never distribute a personal
token as part of the deployment configuration.

## Security boundaries

Input, password and destination mounts must be controlled by trusted administrators.
This is a certificate exporter, not a trust-store verifier: supplied adjacent chain signatures
are checked, but CA trust, revocation and online status are not. No CA certificates are downloaded.
An expired entry blocks the whole snapshot. The last export may itself eventually expire;
health monitoring does not extend its validity. File mode checks depend on the host filesystem.

Private keys are necessarily exported unencrypted for PEM consumers. A PFX password does not
replace filesystem protections. Back up exports only with access controls and encryption.
Logs intentionally omit certificate bodies, keys, passwords and raw exceptions.
No production credentials belong in this repository, issues, CI artifacts or container layers.
See [SECURITY.md](SECURITY.md) for reporting and limitations. No security audit or certification is claimed.

## Development

Python 3.13+ on Linux:

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
ruff check .
pytest -v
pip-audit -r requirements.txt
docker build -t acme-to-files:test .
PYTHONPATH=src:tests python tests/container_smoke.py
```

Tests generate disposable certificates in memory; no real ACME data is used.
